# QIVORA Sync Backend 2.6.1

- Виправлено перевірку ідемпотентності record sync: повторне використання `opId` з іншим `collection`, `recordId`, версією, типом видалення або вмістом тепер відхиляється.
- `pushChanges()` може працювати всередині транзакції, яку відкрив викликач; це використано для атомарного запису Apple Pay-події та record-level зміни.
- У режимі `record` Apple Pay додає транзакцію до `qv_records` через record-sync store та журнал змін. У режимі `snapshot` збережено попередній шлях запису в snapshot.
- Додано backend-тести на повторне використання `opId` для іншого запису/колекції та участь у зовнішній транзакції.
- Додано окрему команду `npm run test:record-sync:backend`, яка запускає лише тести, наявні в backend-пакеті.
- Старий snapshot API та механізм контрольованого перемикання режиму не видалялися.

Перевірка виконана на mock/fake PostgreSQL pool. Реальна PostgreSQL/Render інтеграція в цій перевірці не запускалася.
