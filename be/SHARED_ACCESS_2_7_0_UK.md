# QIVORA Backend 2.7.0 — Shared Access foundation

## Реалізовано в цій кандидатній версії
- Окремі таблиці сімейного простору, учасників, одноразових кодів і запитів на приєднання.
- Код генерується криптографічно випадково, у БД зберігається лише SHA-256 хеш.
- Код має термін дії 24 години; новий код відкликає попередній невикористаний код власника.
- Користувач вводить код зі свого автентифікованого акаунта; власник окремо підтверджує запит.
- Код позначається використаним після схвалення; інші запити за тим самим кодом відхиляються.
- Власник може відкликати невикористаний код.
- Додані API: POST /shared-access/code, POST /shared-access/redeem, GET /shared-access/requests, POST /shared-access/requests/decision, DELETE /shared-access/code?inviteId=..., GET /shared-access/status.
- Виправлено обробку помилки PostgreSQL LISTEN-клієнта: помилка/закриття запускає повторне підключення з наявним backoff.

## Важливі обмеження
Це лише фундамент створення простору та підключення учасників. Фінансові записи ще не переведені на workspace_id і не синхронізуються між членами сім'ї. Не розгортати в production і не активувати міграцію даних, доки не буде реалізовано workspace-scoped record sync, аудит Apple Pay, інтеграційні тести на PostgreSQL та фронтенд.

Схема створюється адитивно в initDb(); існуючі фінансові таблиці/дані не змінюються. Для повного production-релізу потрібні резервна копія БД, перевірка на staging і окреме підтвердження власника.
