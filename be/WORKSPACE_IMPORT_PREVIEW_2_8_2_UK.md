# QIVORA Backend 2.8.2 — розширений попередній перегляд імпорту

## Що змінено
- Read-only preview охоплює `qv_records`, `qv_accounts`, `qv_transfers`, `qv_recurring`, `qv_goals`, `qv_budgets` та `qv_category_budgets`.
- Бюджети й ліміти категорій нормалізуються як окремі записи за ID рахунку, щоб їх можна було переносити через той самий workspace record store.
- Перевіряються некоректна форма колекцій, записи без ID, повторні ID всередині одного персонального джерела, конфлікти з даними простору та tombstone-записи.
- `planHash` тепер включає версії, tombstone-стан і хеші наявних записів робочого простору.
- Preview виконується в транзакції PostgreSQL `REPEATABLE READ READ ONLY`.
- Серверний allowlist workspace/personal record store дозволяє обидві колекції бюджетів.

## Межі цього етапу
- `qv_active_scope` навмисно не імпортується: це вибір активного рахунку конкретного користувача, а не спільні фінансові дані.
- Категорії є вбудованим довідником застосунку, окремої користувацької колекції категорій у поточному фронтенді немає.
- Це лише попередній перегляд. Endpoint копіювання ще не створений; жодні персональні або спільні записи не змінюються.
- Перевірки — автоматизовані модульні та статичні контрактні тести; реальний PostgreSQL integration test у цьому середовищі не виконувався.
- Не розгортати на production без окремої перевірки схеми/резервної копії та підтвердження власника.
